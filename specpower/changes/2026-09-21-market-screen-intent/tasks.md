### 实施中发现并解决的问题（都是测试逼出来的）

1. **澄清分支把筛选回合拦掉了**：`_prequel` 的「没标的就追问」对筛选回合也生效，
   于是回合还没开始就回了「请告诉我代码」。修复：筛选回合跳过该分支。
2. **候选清单原本只存在于证据里**，要靠模型自己写进正文。改为**代码渲染 Markdown
   表格**（与判定卡片同理）：候选不会被写错或漏写，且「量比未提供」变成代码保证的
   一行，而不是"希望模型记得声明"。
3. **模型失败会把清单一起吞掉**：实测账号 Key 无效 → 扫描跑满 61.5s 出了 10 只，
   模型一调就 401，用户只看到「模型鉴权失败」。修复：异常路径也交付候选表
   （`STATUS_DEGRADED`），并如实附上失败原因。这条是**实测踩到的**，不是推演出来的。
4. **校验器真的会拦**：替身模型不声明「量比缺失」时，回合被
   `coverage_unavailable_not_disclosed` 判为降级——诚实性由机器兜住而非提示词。
5. **`TierBudget.target_latency_ms` 此前只赋值、从未被读取**（又一个"声明而不执行"）。
   现在超出即发 `Notice` 并记录，全市场扫描（63.5s vs 中档 30s）因此对用户可见。
6. 替身模型的断言文本写成「候选1 得分最高」时被校验器拒绝（`unsourced_number`）——
   连"1"都要求有出处。这条反过来证明数字校验是真的在工作。

## 第 10 轮附带修掉的两个真实缺陷（都由真实模型实测暴露）

### I1 校验器误判：字段标签里的数字被当成"编造"

真实模型（deepseek-v4-flash）对筛选结果的解读**两次被拒**：

```
数值 1 在所引证据 ['E1'] 中找不到来源（该证据的标量: []）
```

原因不是模型写错：候选行是**文本证据**，标量集合为空，而模型照抄字段名
「候选1」里的那个 `1` 被判成凭空捏造。同类误判会命中**任何字段名带数字的证据**
（`MA20`、`T+3`、`候选1`）以及**所有**文本证据（新闻摘录、公告片段）里的数字。

修复：证据的"内容"包含字段标签与文本正文；纯数字**不做**量级展开（否则
「5020」会被「50.2」匹配，正好放过记错一位数），百分比仍允许与比率互认。
新增 `tests/test_grounding_text_evidence_numbers.py`（6 条，含"不得放宽尺度"的反向用例）。

### I2 筛选回合的提示词没给模型数值

修完 I1 仍降级：原设计「只给证据编号与字段名、不给数值」是为**判定解释**服务的
（防止模型复述数值引入错误）。但筛选任务的数字本身就是内容，模型看不到就只能瞎写。
修复：仅筛选回合把数值一并给出；判定回合保持原样（有测试固定这个分野）。

### 最终实测（真实账号 + 真实模型，非替身）

```
POST /v1/chat  «今天走到好的票，放量票找十个给我» + model_profile_id=c35aa366(deepseek-v4-flash)
→ HTTP 200，76.5s，status=completed
→ 代码渲染的 10 只候选表 + 数据时点 + ⚠️ 未覆盖：量比/换手率
→ 模型逐条解读并**逐条带引用 [E1]…[E12]**，末尾声明「数据未覆盖：volume_ratio（量比）、
  turnover_rate（换手率）、放量确认（量比缺失）」
```

对比修复前：同一请求 `status=degraded, reason=unsourced_number`，用户只能看到
"两次生成均未能给出可溯源的回答"。

用户点名修复：「600519 和 300750 哪个好」只解析出 600519。这类**静默丢信息**
比 400 更危险——用户以为问题被完整理解了。

| 编号 | 问题 | 证据 | 修复 |
|---|---|---|---|
| J1 | `_match_explicit_code` 命中第一个代码就 `return` | 「600519 和 300750 哪个好」→ `('600519.SH', ())` | 新增 `extract_explicit_codes`（正则取**全部** 6 位代码、去重保序）；`_match_explicit_code` 退化为取首个，语义不变 |
| J2 | `TurnRequest.symbols`（批量判定那条路）在对话入口**从未被填充** | 全仓库 grep 无 `symbols=` 赋值；`signal_washout_probe_batch` 从 `/v1/chat` 进不去 | ≥2 个代码构造多标的回合，走批量探针 |
| J3 | `build_turn_request` 的多候选分支**丢掉 `candidates`** | 循环看到"无标的且无候选"，只给泛泛追问；「你说的可能是以下哪一只？…」在生产里从未出现过 | 传下 `candidates`，追问列出候选代码 |
| J4 | 多标的提示词无逐只要求 | 模型最现实的失败是"只谈一只就交卷" | 提示词写明"必须逐只给结论再比较，不得把一只的结论套到另一只" |

`SH600519` / `600519.SS` 仍可识别；「10 只」「2026」不会被当标的。
