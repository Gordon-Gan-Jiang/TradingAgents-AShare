## 1. 问题清单

### 主线一：闭环静默空转

| # | 问题 | 证据（实测） | 性质 |
|---|---|---|---|
| **P1** | 基准缓存与板块面板缓存**无 TTL**，冻结在 2026-08-31，主线兑现闭环**永久死亡** | `benchmark_sh000300.csv` / `ths_industry_panel.csv` 两文件 mtime 均为 8-31 22:17，末行 2026-08-31（今天 9-23）；`mainline_t1_outcomes` **0 行** | **真缺陷** |
| **P2a** | 无法评估时**静默返回空**，无日志无声明 | `evaluate_t1_for_report` 三处 `return []`；`except Exception: bench = pd.Series(dtype=float)` 吞掉失败 | **真缺陷** |
| **P2b** | 调用方**丢弃已算出的原因** | `main.py:1057` 调度器调用后不接收返回值 → `skipped` 里的原因被扔掉 | **真缺陷** |
| **P3** | 弃权判定不落库（**设计如此**）→ 校准样本不足，但该事实不可见 | 探针 47 次调用 vs `signal_verdicts` **3 行**；探针 57% 降级 | 缺披露 |
| **P4** | 用户数据类表为空 | `trade_ledger` 0（等成交流水）、`feedbacks` 0、`recommendation_eval_items` 0（端点按需触发，从未调用） | 等数据/未触发 |

**P1 的因果链**（每一环都实测过）：

```
缓存无 TTL（只要文件在就无条件返回，mainline_backtest.py:45 / :91）
  → 基准序列末行恒为 2026-08-31
  → evaluate_t1_for_report: check_date(8-31) <= trade_date(9-x) 恒真
  → return []                     ← 静默，无日志
  → 调用方 if outs 判否，skipped 也不记（调用方自己就把返回值扔了）
  → mainline_t1_outcomes 0 行
  → t1_overview 永远空 → 「昨日主线今日兑现了吗」永远答不出来
```

**为什么这是本轮最该修的**：它不是"缺功能"，而是**一个正确的功能被一个缓存 bug 永久关掉，且全程无人知道**。修完立刻恢复 6085 行那一档的闭环能力。

## 2. 修复方案

### P1 —— 缓存加 TTL，且陈旧时**必须尝试刷新**

**修法**：`fetch_benchmark_close` / `fetch_ths_board_panel` 的 `cache=True` 语义从
"文件存在就用" 改为 **"文件存在且不够旧才用"**。

```python
# 现状（无条件信任）
if cache and cache_path.exists():
    return pd.read_csv(cache_path, index_col=0)

# 改为
if cache and cache_path.exists():
    cached = _read_cache(cache_path)
    if not _is_stale(cached, max_age_days=max_age_days):
        return cached
    # 陈旧 → 落到下面的实时抓取；抓到就覆盖缓存
```

**关键设计决策**：

* **判据用"数据末日"而非"文件 mtime"**。mtime 只说明什么时候写的；
  数据本身可能写的时候就旧。判据：`缓存末行日期 < 今天 - max_age_days（按交易日算）`。
* **TTL 可配**（env），默认取 3 天——覆盖周末 + 一天缓冲。
* **实时抓取失败时仍然返回陈旧缓存**：可用性优先于新鲜度（有旧数据好过没数据）。
  但这**不能静默**——由 P2 负责声明。两者是配合关系，缺一不可：
  只加 TTL 修不好"抓不到"，只加声明修不好"永远抓"。

### P2a —— 无法评估时**声明**，不要返回空

`evaluate_t1_for_report` 现在的三处 `return []` 语义不同，必须拆开：

| 场景 | 现在 | 改为 |
|---|---|---|
| `not trade_date or not mainlines or not report_id` | `return []` | 保留（这是脏数据，调用方已有校验） |
| `len(le) == 0`（基准完全没有可用日期） | `return []` | **抛异常**，让调用方记进 `skipped` |
| `check_date <= trade_date`（**前瞻数据还没到**） | `return []` | 保留 `return []`，但**区分**它是合法等待 |
| 基准抓取抛异常 | `bench = 空序列` | 记下原因，供上面判断时使用 |

**判据**（避免把"合法的还没到时间"误报成故障）：

* 基准末行日期 **< 今天之前最后一个交易日** → **陈旧/不可用 → 声明**
* 基准末行日期 **正常，只是不够 trade_date 的前瞻** → **合法等待 → 静默返回空**

### P2b —— 调用方不要把原因扔掉

`main.py:1057` 改为接收返回值并记录 `evaluated_reports` 与 `skipped` 摘要。
与工具层的既有原则一致：**失败必须让用户（或至少运维）看见**。

### P3 —— 不改落库逻辑，只补披露

"弃权判定不落库"的理由是充分的（弃权没有可检验的预测，计入命中率会污染分母）。
**不动它**。要补的是：当校准样本数低于阈值时，明确声明"样本不足，原因是多数判定弃权"，
而不是让 `/calibration` 静默显示空白。

### M2/M3/M4 —— 让闸门守住真正要守的东西

| 改动 | 做法 |
|---|---|
| **M2** | `check.sh` 增加**规划层口径**闸门：`--golden --with-planner`（需 `TA_PLANNER_USER_ID`），阈值按规划口径单独设（实测 88%/96%，取 0.80/0.85）。**两个口径两套阈值，各自标注** |
| **M3** | 默认 `check.sh` 至少跑**离线**黄金集闸门（成本低、无需模型）；规划层闸门作为可选（要花 LLM 调用） |
| **M4** | 把 `verify_tool_turns.py` 接进 `check.sh`（可选档，因它走真实回合、要花模型调用） |

**注意成本**：规划层闸门 = 50 次 LLM 调用；端到端套件 = 35 次回合。
两者都不适合每次提交跑，所以放"可选档"并把**它守什么口径**写在输出里，
避免又出现"跑了闸门就以为守住了生产"的错觉。

### M5 —— 把"单次采样不可信"变成代码约束

在归因端点已返回方差警告的基础上，补一个**可复用的重复采样助手**：
同问同配置跑 N 次，返回中位数与离散度；**N < 3 时拒绝给出"变快/变慢"的结论**。
这样"单次采样"这件事在 API 层面就做不出来，而不是靠纪律。

## 3. 任务拆分（TDD）

每个任务**先写测试再实现**。测试必须能**在修复前失败**（否则它没在测任何东西）。

- 测试：缓存文件末行日期陈旧时，**必须**调用实时抓取（用假 ak_module 断言被调用）
- 测试：缓存新鲜时，**不得**调用实时抓取（秒回是既有承诺）
- 测试：实时抓取失败时，**仍返回陈旧缓存**（可用性优先），且不抛异常
- 测试：`max_age_days` 边界（恰好等于阈值 / 超出）
- 实现：`mainline_backtest.py` 的 `fetch_benchmark_close`

### T2 · 板块面板缓存 TTL（P1）

- 测试：基准**陈旧**时，`evaluate_t1_for_report` **不得静默返回 `[]`**，必须让调用方拿到原因
